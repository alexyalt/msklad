## Диагностика ошибки 400 (подтверждена на тестовом аккаунте)

Запросы curl к `api.moysklad.ru` (basic auth `admin@manubad`, тестовый аккаунт):

| Запрос | Код |
|---|---|
| `entity/assortment?filter=id=<uuid>` | 200 |
| `entity/assortment?filter=id=<полный href>` | 400, «Неверное значение '…' параметра фильтрации 'id'» |
| `report/stock/all?filter=product=<полный href>` | 200 (href допустим) |

Причина в коде: `DocumentRepository.addItemByHref()` строит `assortment?filter=id=$productHref`, где
`productHref` — полный href из офлайн-снимка (`OfflineItem.href`). `pushPending()` вызывает именно
`addItemByHref`, поэтому синхронизация обрывается на первой же строке очереди. Та же ошибка молча
глотается в `assortmentInfo()` (`if (400) continue`) — из-за этого у части строк снимка нет наименований.

Решение: нормализовать значения фильтра `id=` до UUID (последний сегмент href) в `addItemByHref()` и
`assortmentInfo()`. Хранимый формат (href) не меняем — он нужен для сверки позиций документа
(`positions[].assortment.meta.href`).

### Решения по дизайну (сессия 2)
- Дубли при прерванной синхронизации: `pushPending` бросал исключение посреди цикла, VM не сохраняла уже
  отправленные строки → при повторе они уходили второй раз. Добавлен колбэк `onSent(line)`: VM снимает строку из
  очереди и сохраняет снимок сразу после успешной отправки.
- Автосинхронизация при выключении офлайна: только выгрузка очереди (без перезагрузки снимка — быстрее, сканы
  блокируются на время Loading). При ошибке переключатель возвращается в «офлайн» (очередь не потеряна, кнопка
  синхронизации снова видна), сообщение `sync_auto_failed`.
- Журнал: `ScanEntry` перенесён в `data/ScanJournal.kt`, хранение в SharedPreferences `journal` (Gson),
  свежие сверху, номер = `seq` (сквозной, сбрасывается при очистке), лимит 200 — вытесняется самая старая.
- Удаление из журнала в офлайне снимает из очереди ровно количество строки (`withoutPendingType`), а не всю позицию
  (`withoutPending` удалял всё по товару — баг). Если в очереди количества нет (строка уже выгружена) и мы офлайн —
  ошибка «удалите в онлайн-режиме». Онлайн: если в очереди есть количество — снимаем локально, иначе — с сервера.
- Undo-«✕» в зоне результата удалён вместе с `undo()`/`canUndo`/`ResultState.Undone`.
