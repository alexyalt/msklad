# ТЗ: Сканер для документа «Перемещение» МойСклад (Android, Kotlin)

## 1. Общее назначение

Android-приложение для наполнения готового документа «Перемещение» в системе МойСклад. Пользователь сканирует или вводит вручную коды товаров, приложение добавляет позиции в документ и показывает остатки товара на складе-источнике и складе-получателе.

## 2. Технологический стек

- Язык: Kotlin
- Платформа: Android (minSdk 24+)
- Сканирование: CameraX + ML Kit Barcode Scanning (живой поток)
- Сеть: Retrofit / OkHttp + Gson/Moshi
- API: МойСклад REST API 1.2 (https://api.moysklad.ru/api/remap/1.2)
- Авторизация: Basic Auth (логин/пароль) или Bearer-токен
- Архитектура: MVVM
- Звук: SoundPool (success/error)
- Визуальная индикация: цветовая подсветка зоны вывода, Snackbar
- Сборка: GitHub Actions → APK artifact

## 3. Экран настроек

### 3.1. Поля ввода

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| Логин | Text | Да | Логин для API МойСклад |
| Пароль | Password | Да | Пароль для API МойСклад |
| Номер или ID перемещения | Text | Да | Номер или UUID готового документа «Перемещение», созданного в веб-интерфейсе |

Убрано: выбор типа документа (только «Перемещение»).

### 3.2. Логика

- При сохранении — валидация заполненности.
- При нажатии «Начать» — приложение ищет документ по номеру или ID, получает его данные (склад-источник, склад-получатель), переходит на главный экран.
- Если документ не найден или не является «Перемещением» — ошибка на экране настроек.
- Настройки сохраняются локально.

## 4. Главный экран

Три зоны, с изменённой логикой сканера.

### 4.1. Зона сканера (верхняя)

- Предпросмотр камеры (PreviewView) с распознаванием штрихкодов в реальном времени.
- Кнопка «Включить/Отключить сканер» — переключатель, который останавливает или запускает поток камеры, чтобы не расходовать батарею, когда сканирование не нужно.
- При успешном распознавании — немедленная отправка запроса в API (без переключения экранов).
- Защита от повторного срабатывания на один код (debounce 1–1.5 сек).

### 4.2. Зона ручного ввода (средняя)

- Поле «Код или штрихкод товара» — текстовый ввод.
- Поле «Количество» — числовой ввод (опционально, по умолчанию 1).
- Кнопка «Отправить» — выполняет тот же запрос, что и сканирование.

### 4.3. Зона вывода ответа API (нижняя)

- Отображает результат последнего запроса.
- Цветовая индикация: зелёная — успех, красная — ошибка.
- При успехе отображается:
  - название товара;
  - остаток на складе-источнике (после вычета добавленного количества);
  - остаток на складе-получателе (текущий, до операции или с учётом уже добавленного в документ).
- При ошибке — текст ошибки, ожидание следующего ввода.

## 5. Логика работы

### 5.1. Обработка кода (сканирование или ручной ввод)

1. Получен код или штрихкод.
2. Поиск товара:
   - Запрос: `GET /entity/assortment?filter=search=<код>` — поиск по коду или штрихкоду. API МойСклад поддерживает поиск по штрихкоду через параметр search (полное соответствие) и по коду.
   - Если товар не найден — ошибка.
3. Проверка остатков:
   - Получить остаток товара на складе-источнике и на складе-получателе.
   - Запрос: `GET /report/stock/all?filter=product=<id>;store=<id>` для каждого склада (или один запрос с двумя складами, если API позволяет).
4. Добавление в документ «Перемещение»:
   - Получить текущий документ: `GET /entity/move/<id>`.
   - Добавить позицию в `positions` с указанным количеством.
   - Отправить `PUT /entity/move/<id>`.
5. Вывод результата:
   - Успех: зелёная подсветка, звук успеха, название товара, остаток на источнике (с учётом вычета), остаток на получателе.
   - Ошибка: красная подсветка, звук ошибки, текст ошибки.

### 5.2. Отображение остатков

- Источник: остаток после вычета количества, добавленного в документ (если API возвращает актуальные данные после PUT).
- Получатель: текущий остаток (до или с учётом добавленного — уточнить в реализации, рекомендуется показывать «стало» после обновления документа).

## 6. Работа с API

### 6.1. Авторизация

- Basic Auth или Bearer-токен (из настроек).
- Заголовок `Accept-Encoding: gzip` обязателен.

### 6.2. Основные запросы

| Действие | Метод | Эндпоинт |
|---|---|---|
| Поиск товара по коду/штрихкоду | GET | `/entity/assortment?filter=search=<код>` |
| Получить документ «Перемещение» по ID | GET | `/entity/move/<id>` |
| Обновить позиции документа | PUT | `/entity/move/<id>` (с обновлённым `positions`) |
| Получить остатки по товару и складу | GET | `/report/stock/all?filter=product=<id>;store=<id>` |

Примечание: для получения ID документа по номеру может потребоваться отдельный запрос `GET /entity/move?filter=name=<номер>`. Если API не поддерживает фильтрацию по номеру, пользователь вводит ID (UUID) документа.

## 7. Сборка и тестирование

- GitHub Actions: push → JDK 17 → `./gradlew assembleDebug` → APK artifact.
- Нейросеть (syntx.ai) пушит код в GitHub.
- Пользователь скачивает APK из Actions и тестирует на смартфоне.

## 8. Ограничения

- Только документ «Перемещение».
- Документ создаётся заранее в веб-интерфейсе МойСклад.
- Приложение не создаёт новые документы, только добавляет позиции в существующий.
- Язык интерфейса — русский.

## 9. Критерии готовности

- Экран настроек: логин, пароль, номер или ID перемещения.
- Поиск документа по номеру или ID при старте.
- Главный экран с тремя зонами.
- Сканер с кнопкой включения/отключения потока.
- Ручной ввод кода/штрихкода и количества.
- Поиск товара по коду или штрихкоду.
- Добавление позиции в документ «Перемещение».
- Отображение остатков на двух складах (источник и получатель).
- Звуковая и цветовая индикация.
- GitHub Actions собирает APK.
