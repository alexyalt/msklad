# ARCHITECTURE — msklad scanner

## Обзор

Android-приложение (Kotlin, single-module `app`) — сканер штрихкодов для учёта товаров в МойСклад.
Работает с документами «Перемещение» (`entity/move`), «Оприходование» (`entity/enter`) и
«Списание» (`entity/loss`): ищет товар по штрихкоду/коду/артикулу, добавляет позиции в документ,
показывает остатки «ИЗ → В». С версии 1.5 умеет работать с локальной копией остатков (офлайн-режим)
и выгружать накопленные позиции в документы по кнопке синхронизации.

Стек: Kotlin 2.0.20, AGP 8.5.2, compileSdk 34, minSdk 24, ViewBinding, Material 3,
Retrofit 2 + Gson + OkHttp, CameraX + ML Kit barcode, корутины + StateFlow.

## Точки входа

- `SettingsActivity` — LAUNCHER. Сохраняет настройки, резолвит документы (перемещение обязательно,
  оприходование/списание — если заданы), кладёт `DocInfo` в кэш `OfflineStore`, при нажатии «Начать»
  открывает `MainActivity`.
- `MainActivity` — экран сканирования. Получает `DocInfo` перемещения через Intent (process death safe),
  документы оприходования/списания читает из `OfflineStore`.
- `LabelActivity` — открывается с экрана сканирования, если в настройках задан сервер печати.

## Потоки данных

### Единицы измерения
`product.uom` в API — объект `{"meta":{"href":"…/entity/uom/<uuid>"}}` без имени, поэтому `uomName()`
сначала пробует раскрытое поле `name`, затем ищет id в справочнике `entity/uom` (загружается один раз
за сессию, кэш `uomCache`). Используется в добавлении позиции, поиске товара, офлайн-снимке и списке
последних сканов. Если у товара единица не задана вовсе (`uom: null`), возвращается базовая
единица учёта `шт` (`DEFAULT_UOM`), иначе в строке оставалось бы только число.

### Онлайн-скан
`MainActivity` (камера/клавиатура) → `MainViewModel.submit(code, qty)` → `DocumentRepository.addItem(doc, …)`
→ `entity/assortment` (поиск товара) → `entity/{type}/{id}` (позиции) → `report/stock/all` (остатки)
→ `PUT entity/{type}/{id}` (позиции) → `AddResult` → `ResultState.Success` → отрисовка «ИЗ → В» + uom.

### Офлайн-снимок (загрузка при включении переключателя «Офлайн» на экране сканирования)
`MainViewModel.setOffline(true)` → `enableOffline()` → `DocumentRepository.loadSnapshot(move, supply, loss)`:
1. `report/stock/all?filter=store=<source>` (постранично) — остатки исходного склада;
2. то же для целевого склада;
3. `entity/{enter|loss}/{id}?expand=positions.assortment` — позиции документов корректировки;
4. объединение href → `entity/assortment?filter=id=<uuid1>;id=<uuid2>;…` батчами по 50 (только UUID: полный href
   и разделитель «,» в фильтре `id` дают 400, код 1014) — название, код, артикул, штрихкод, ед. изм.
   (единица измерения в API приходит только как meta-ссылка, имена берутся из справочника `entity/uom`);
5. `OfflineStore.save(snapshot)` (неотправленные `pending` сохраняются), сводка «склад — кол-во наименований —
   количество» → блок названия/кода и `OfflineStore.saveLastSync()` (показывается на экране настроек).
Без связи: если в памяти есть прежняя копия — работа по ней (сообщение с её датой), иначе офлайн не включается.
Кнопки «Офлайн остатки» в настройках больше нет (1.6.0); там только «Последняя синхронизация».

### Офлайн-скан и синхронизация
**Живые остатки (1.6.1).** `OfflineSnapshot.items` — базовый остаток (сервер на момент загрузки + уже
отправленные строки, `baked(line)`), `pending` — неотправленные операции. Текущий остаток =
`items` + вклад всех `pending` (`sourceQty/targetQty(href)`): оприходование +к складу-источнику, списание −,
перемещение − источник / + цель. Проверка «достаточно ли» (`available(href)`) не зависит от вкладки документа,
поэтому офлайн-оприходование сразу доступно для списания/перемещения. Сводки — по `effective()`.
Скан в офлайн-режиме → поиск по локальному индексу (barcode → code → article) → проверка локального
остатка → `PendingLine` в `OfflineSnapshot.pending` → `ScanEntry(offline = true)` (в журнале жирным).
Выгрузка — `DocumentRepository.pushPending(...)` в порядке **оприходование → списание → перемещение**:
- каждая отправленная строка сразу снимается из очереди (`onSent`) и снимает жирное выделение у сканов товара;
- ошибка конкретной строки (недостаточно товара и т.п.) не прерывает выгрузку → `SyncOutcome.failed`
  (строка остаётся в очереди, в журнале жирная + красная);
- прерывает выгрузку только `Throwable.abortsBatch` (IOException, 401/403, 429 после 3 повторов с паузой, 5xx) —
  повторная синхронизация продолжает с оставшихся строк; темп запросов ограничен `RateLimitInterceptor` (2/с).
Ручная синхронизация (стрелки, только офлайн) = выгрузка + перезагрузка остатков. Слева от стрелок — время
последней синхронизации (`lastSyncAt`), рядом кнопка текстовой выгрузки.
Выключение переключателя → `disableOffline()`: выгрузка очереди; если очередь опустела — `goOnline()`:
`OfflineStore.clearRemnants()` (удаляются локальные остатки и очередь; документы и итог синхронизации остаются),
онлайн. Если остались строки — офлайн не выключается, итог в блоке названия/кода.
Итоги синхронизации и служебные сообщения (`ResultState.Synced`, `Removed`) выводятся в блок названия/кода
под кнопками П/О/С, а не в нижнюю зону сообщений (её частично перекрывает журнал).

### Текстовая выгрузка офлайн-сканов
`data/OfflineExport.kt`: `{буква документа}√{код}√{количество}√√` на строку (по одной на тип+товар, количество
суммарное, порядок О → С → П, затем по коду). Показывается в диалоге с нередактируемым EditText (выделение/копирование
системным меню, без разрешений на буфер обмена и файлы), единственная кнопка «Закрыть».

### Журнал последних операций
`MainViewModel.recordScan()` добавляет `ScanEntry` в начало списка → `ScanJournal.save()`. Удаление строки — только
из журнала, через диалог подтверждения (ДА красная / НЕТ зелёная): если количество строки ещё в офлайн-очереди —
снимается локально `withoutPendingType`, иначе `DocumentRepository.removeQuantity()` (онлайн). Офлайн-сканы (жирные)
всегда снимаются только локально. Кнопка «Очистить журнал» — последним элементом прокручиваемого списка, с
подтверждением; с 1.6.0 очищает и очередь офлайн-сканов (`OfflineStore.clearPending()`), снимая ошибки
синхронизации — после этого офлайн можно выключить. Документы в МойСклад и загруженные остатки не трогает.

## Внешние зависимости

- МойСклад JSON API 1.2 (`https://api.moysklad.ru/api/remap/1.2/`), Basic auth, лимит 2 запроса/сек
  (`RateLimitInterceptor`).
- CameraX 1.3.4 + ML Kit barcode-scanning 17.3.0.
- Сервер печати этикеток (опционально, свой Flask в `labelserver/`).
- GitHub Actions: сборка `assembleDebug`, публикация APK в релиз `latest` из `main`.

## Известные ограничения
- Офлайн-остатки ведутся по складам перемещения (источник/цель); оприходование и списание в офлайне меняют
  остаток склада-источника перемещения, даже если в самих документах указан другой склад.
- В снимок попадают только товары с движением на складах перемещения и позиции документов: товар без
  истории (нет в `report/stock/all`) офлайн не найдётся («не найден в локальной копии»).

- Нет юнит/инструментальных тестов; проверка — сборка в CI.
- Офлайн-снимок — плоская копия на момент загрузки; конкурентные изменения на сервере не мержатся
  (конфликты при синхронизации разрешает сервер, ошибка показывается пользователю целиком).
- Признак «не принято сервером» (красная строка журнала) хранится только в памяти ViewModel: после перезапуска
  экрана строки остаются жирными, а красными станут после следующей синхронизации.
- Текстовая выгрузка агрегирует количество по (тип документа, товар), а не по отдельным сканам.
- Штрихкоды в офлайн-снимке доступны только если успел отработать батч `entity/assortment?filter=id=…`;
  при его сбое поиск идёт по коду и артикулу.
- `labelActivity` требует сетевого сервера печати; в офлайне не работает.
- Режим «только внутренние штрихкоды» фильтрует лишь камеру: ручной ввод и коды/артикулы проходят всегда.
- Единицы измерения кэшируются на сессию репозитория; при недоступном справочнике `entity/uom`
  количество выводится без единицы, сканирование не прерывается.

## Журнал изменений архитектуры

- 1.5.3 — фильтр `id=` в `entity/assortment` строится из UUID (`uuidOf(href)`), условия через «;» (исправлена
  ошибка 400 при синхронизации офлайн-очереди); `pushPending(onSent)` — построчное снятие из очереди; автосинхронизация
  при выходе из офлайна; новый модуль `data/ScanJournal.kt` (персистентный журнал, `ScanEntry` перенесён из
  `MainViewModel`); удалены undo «✕» в зоне результата и `MainViewModel.undo()/canUndo`; переключатель офлайна
  убран из настроек (флаг `Settings.offlineMode` меняется только с экрана сканирования).

- 1.5.2 — журнал сканирований переведён с `LinkedHashMap<productHref, ScanEntry>` на
  список записей `ScanEntry(seq, …)`: одна строка на скан, у каждой буква операции
  (`DocumentType.journalLetter`: П/О/С), отмена снимает ровно свою строку;
  `report/stock/all` читается по `meta.href` (поля `assortment` в отчёте нет) и `stockQuantity()`,
  из-за чего офлайн-снимок раньше сохранялся с нулевыми остатками;
  `uomName()` при отсутствии единицы у товара отдаёт базовую `шт` (`DEFAULT_UOM`);
  формат строки результата — `[из] (кол) {в}`;
  офлайн-режим хранится в `Settings.offlineMode`, от него зависит доступность кнопки
  «Офлайн Синхронизация».
- 1.5.1 — оприходование исправлено на `entity/enter` (`supply` — это Приёмка, другой документ);
  добавлено разрешение единиц измерения через справочник `entity/uom` с кэшем на сессию (в API `uom`
  у товара — meta-ссылка без имени, из-за чего единицы не выводились); чтение документа устойчиво к
  неподдерживаемому `expand` (фолбэк без раскрытия + дочитывание имени склада через `entity/store/{id}`);
  в настройках появился режим «только внутренние штрихкоды» (сканирование принимает лишь коды,
  начинающиеся с `2`, EAN-13 производителей игнорируется); формат строки результата —
  `ИЗ (10 шт) - (1 шт) - В (2 шт)`, для корректировок `было (10 шт) - (-1 шт) - стало (9 шт)`.
- 1.5 — `MoveRepository` заменён на `DocumentRepository` (поддержка move/supply/loss);
  добавлены `OfflineStore`, `OfflineModels`, офлайн-режим в `MainViewModel`; `AddResult` расширен
  полями `uom`, `docType`, `storeBefore`, `storeAfter`; в `SettingsStore` добавлены
  `supplyInput`/`lossInput`; `MoySkladApi` получил generic-эндпоинты документов и постраничный отчёт.
- 1.4 — список последних сканов на 50 позиций, режимы ввода (сканер/смешанный/клавиатура).
- 1.3 — экранная цифровая клавиатура, имя до 50 символов, версия в настройках.
- 1.2 — печать этикеток через внешний сервер.
- 1.1 — ограничение частоты запросов, сессия сканирования.
- 1.6.0 — загрузка офлайн-остатков перенесена из настроек на включение переключателя «Офлайн»; после полной
  выгрузки при выключении локальные остатки удаляются (`OfflineStore.clearRemnants`). `pushPending` больше не
  прерывается ошибкой отдельной строки (`SyncOutcome.failed`, `FailedLine`), прерывание — только `abortsBatch`,
  повтор на 429. `ScanEntry.offline` (жирные строки журнала). «Очистить журнал» очищает очередь офлайн-сканов.
  Итоги синхронизации — в блоке названия/кода и в `OfflineStore.lastSync*` (экран настроек). Новый модуль
  `data/OfflineExport.kt` + диалог текстовой выгрузки.
- 1.6.1 — офлайн-операции меняют локальные остатки (живой остаток = база + очередь, запекание при отправке);
  выгрузка `X;код;кол-во;;` с копированием (поле + кнопка «Копировать», ClipboardManager); ошибка
  сканирования выводится в блоке результата вместо нижней зоны/Snackbar; время синхронизации — только `HH:mm`.
